# editor-vanjs

Standalone Savanna editor for editable HTML files. Uses **vanjs-core**, **vanjs-ext (VanX)**, and the **same JSX runtime source as shared-vuejs**. The editing canvas comes from **`shared-vuejs/canvas`**; previews and presentation artwork use **`shared-vuejs/renderer`**, sharing ShapeView, text, table, group, image and effect components with the Vue editor. The native UI uses buttons, inputs, range sliders, color pickers, selects, details, dialogs and `title` tooltips. Icons are Unicode. It has no Vue, router, Pinia, Naive UI, icon fonts, service worker, backend requirement. The working copy is persisted locally in IndexedDB.

## Run

From the workspace root:

```sh
npm run dev:vanjs    # http://127.0.0.1:5174
npm run build:vanjs  # editor-vanjs/dist/index.html and editor.js
npm run test:vanjs   # unit tests + headless Chrome integration test
```

Open `dist/index.html` directly, including over `file://`, or extract `dist/editable-editor.zip`. Saving downloads an editable ZIP with separate content and assets. Use **Single Editable HTML** to download a self-contained editable document.

ZIP contents:

```text
index.html       # Small HTML entry point
document.js      # Native document data; media paths instead of base64
editor.js        # Combined editor and shared artwork renderer
editor.css       # Native editor UI stylesheet
renderer.css     # Shared artwork styles
assets/          # Binary images, video, audio, etc.
manifest.json    # Inventory with file sizes and media types
```

Media aliases share one file. `document.js` stores the document structure and loads both over HTTP and directly from `file://`; media remains in `assets/`. To repackage local media from an extracted ZIP, serve its folder over HTTP; browsers restrict reading sibling local files.

The runtimes retain stylesheet fallbacks for programmatic mounting; extracted pages load `editor.css` and `renderer.css`. Keep the renderer stylesheet with `editor.js` when replacing an older exported runtime.

Run `npm run analyze` in this directory to rebuild and open `stats.html` for the combined interactive bundle visualizer. Set `SAVANNA_LOCAL_CORE=1` to analyze the local core build, including its inline source maps. Per-output reports and esbuild dependency graphs are in `dist/stats/`; generated output, including inline source maps, is shown separately from module contributions. The build reports raw, gzip and Brotli sizes in `dist/bundle-report.json`. It rejects Vue/UI-library dependencies and enforces a **1.5 MiB gzip editor runtime** budget. Charts use SVG previews generated by the Vue editor and do not require ECharts in VanJS. Content and media are separate from this runtime budget. There are no CDN imports; all required scripts are included in the ZIP. Both UI and renderer use the same VanJS singleton. ZIP writing uses standard stored entries, avoiding another runtime dependency.

The Vue editor offers **File → Editable ZIP (VanJS)** and **File → Single Editable HTML (VanJS)**. Both flush pending edits and include the native document, layouts, masters, themes, media, and VanJS editor. **Single Page HTML** carries the same document and media with a presentation-only runtime; it renders slides on demand and contains no editor. **Zip HTML** remains available separately.

The Vue editor's **Open** command and dashboard accept single editable HTML and newly exported Single Page HTML files. Both contain the editable document data. Import reads that data without running the file's scripts, restores media into the local workspace, and opens a new local copy. Older presentation-only exports without document data and arbitrary HTML pages cannot be imported as editable documents.

## Local store and on-demand loading

The editor owns a local store (`src/store.mjs`) backed by the `savanna-vanjs-editor` IndexedDB database. The UI observes the store's active view, slide metadata, history, loading/error signals, and UI state. Shape models, assets, thumbnails, and undo journals are separate records. Only the active slide and its layout, master, theme, and referenced assets are loaded into the working view. Media uses scoped object URLs that are revoked when the view is replaced.

Slide selection flushes pending writes, reads the selected records, and mounts shared edlib's `SlideEdit`. A request generation prevents an older load from replacing a newer selection. Clean canvas navigation uses edlib's mutation revision instead of serializing the outgoing slide. Thumbnail rows are keyed by slide ID, selection styling is independently bound, and only visible previews are rendered; cached previews live in IndexedDB. Edits invalidate the affected preview, while file-wide changes invalidate all previews.

The Vue application's VanJS route passes a same-origin source bridge, backed by the same slide/theme/OPFS loaders as the Vue editor. It passes metadata to the iframe and fetches records on demand instead of assembling an export of the whole deck. Its working copy is isolated by file ID/source timestamp and survives reopening that source. Bootstrap document data is released after it is loaded into its workspace.

```js
await SavannaVanEditor.ready(); // renderer scripts
const editor = SavannaVanEditor.mount(host, { document });
await editor.ready; // IndexedDB import and first slide
await editor.selectSlide(slideId);
await editor.flush();
const snapshot = await editor.getDocument(); // explicit full-deck assembly
```

`load`, `undo`, `redo`, `getDocument`, `selectSlide`, and `flush` are asynchronous. `onChange` receives `{ workspace, slideId, revision }`; consumers request a full document explicitly when needed. `editor.store` exposes signals and subscriptions. Direct store consumers must treat view values as read-only and call `commit(nextView)` with a detached edited view.

Undo journals contain changed records and lightweight file metadata, with a default limit of 100 steps; they do not keep full-deck snapshots in memory. Exports assemble a consistent full document only on request and preserve stable media targets and unknown metadata. Failed writes leave the dirty view and pending records available for recovery export, surface an error, and block slide eviction after a write failure. `destroy()` disconnects the UI and closes the database after pending writes settle; it retains the persisted working copy.

## Implemented core

- Add, duplicate, delete and reorder slides; thumbnails, slide background and presentation dimensions.
- Native shapes (text, rectangle, ellipse, triangle, line), local image insertion with embedded data URLs, basic SVG path rendering, group rendering, layout/master backgrounds and shapes. Imported artwork uses the same shared rendering code, including gradients, effects, cropped images, groups, tables and styled text.
- Multi-selection; pointer movement/resizing; position, size and rotation; fill and outline; locking, visibility and layer order; alignment; duplication/deletion.
- Text replacement and whole-shape font family/size, bold/italic, color and paragraph alignment; rendering of styled runs.
- Main/trigger animation lists, drag/drop ordering and keyboard-accessible move buttons, start/duration/delay, deletion and fade insertion. Animation timing stays in the native model.
- Undo/redo with atomic pointer gestures; keyboard shortcuts; dirty tracking and native unsaved-document confirmation; editable ZIP and self-contained HTML saving.
- Static presentation view with arrow-key navigation.
- Explicit mount/destroy lifecycle, multiple independent editor instances, change callbacks and error callbacks.

**Editing controls are not yet at full editor-vuejs feature parity.** The renderer now shares the original implementation; there is no second geometry/text renderer. Dedicated controls for charts, tables, SmartArt, complex presets, gradients/effects, group internals, cropping, rich text ranges and hyperlinks are still migration work, along with animation playback/motion paths, document pagination, PPTX/DOCX import/export, collaboration, AI tools and publishing. Existing data is retained and displayed by the shared renderer. Font fidelity requires the original fonts; the export bridge includes registered local font assets when available.

Keep optional heavy features behind separately loaded adapters. Do not import the full `shared-vuejs/editor`/WorkCanvas graph into this runtime: its transitive imports would defeat the embedding size goal. The framework-free model and document packaging utilities are reused by the existing editor's export bridge.

## Embed

The IIFE publishes `window.SavannaVanEditor` and automatically mounts when a `[data-savanna-editor]` element is present. Packaged HTML loads `document.js` before the editor runtime. For legacy inline embedding, full native JSON in a script with `id="savanna-document"` and `type="application/json"` remains supported. The build's generated files demonstrate the package contract.

For explicit mounting, wait for the local shared renderer to load:

```js
await SavannaVanEditor.ready();
const editor = SavannaVanEditor.mount(hostElement, {
  document: { version: 1, file: { width: 1280, height: 720, name: 'Deck' },
    slides: [{ id: 'slide-1', shapes: [] }], assets: {}, layouts: [], masters: [] },
  onChange(document) { /* Detached native JSON snapshot */ },
  onError(error) { console.error(error); },
  // Optional: provide the built IIFE text if loading through a module loader.
  getRuntime: async () => runtimeSource,
  getStyles: async () => stylesheetSource,
});
await editor.ready;
const snapshot = await editor.getDocument();
await editor.load(otherDocument);
await editor.undo();
await editor.redo();
await editor.saveZIP();
await editor.saveSingleEditableHTML(); // saveHTML remains a compatibility alias
await editor.saveJSON();
editor.destroy();
```

Give the host a definite height. Native UI styles are scoped to `.ve-editor`; artwork uses the shared `.slide` styles. The shared editing canvas uses the app’s 1px-root rem coordinates while mounted and restores the host root font size on destruction. Explicitly mounting again on the same host destroys its previous instance.

`slides` must contain complete native shape objects, not slide metadata/IDs. `fileInfo` and raw exported file objects with complete `slides` are accepted as input too. Unknown document and shape properties survive opening/saving. Layouts and masters are separate arrays; raw exported mixed `layouts` are separated by `parentid`. Assets map native media target names to data URLs (or `{data}`/`{url}` objects). External media must be readable with CORS to package it; missing or inaccessible media causes ZIP saving to fail with a visible error.

Text replacement intentionally applies the first run's format to new text. Formatting controls apply to whole selected shapes. Undo restores original rich-text runs.

Production builds are minified by default. The development watch build stays readable; to minify it as well, run:

```sh
npm --prefix editor-vanjs run dev -- --minify
```

The build resolves the public renderer import to current workspace shared-library source, avoiding a stale installed tarball. `npm run build:shared` also produces the public `shared-vuejs/renderer` and `shared-vuejs/renderer.css` exports for packaged consumers. Renderer services are injected through a small shared port; importing it does not initialize editor stores, persistence, routing or Vue.

## Structure

- `src/components/native.jsx`: reusable, accessible native controls.
- `src/model.mjs`: framework-free native-model operations.
- `src/store.mjs` and `src/local-db.mjs`: reactive local state, record-sized IndexedDB persistence, and persisted undo journals.
- `src/thumbnails.jsx`: keyed, visible-only slide previews and their persisted cache.
- `src/document.mjs`: legacy JSON/HTML loading, safe serialization and file utilities.
- `src/package.mjs`: ZIP package layout, media extraction/deduplication and import.
- `src/zip.mjs`: dependency-free ZIP32 writer and validated stored/deflated reader.
- `src/render.jsx`: native selection/event adapter around the shared renderer; no artwork implementation.
- `src/shared-renderer-entry.jsx`: bundles the public shared renderer and original artwork CSS.
- `src/renderer-loader.mjs`: local renderer loading and ZIP resources.
- `src/editor.jsx`: VanJS/VanX editing UI and lifecycle.
- `src/index.jsx`: self-loading/explicit embedding API and stylesheet installation.
- `scripts/build.mjs`: runtime build, extracted demo, example ZIP and bundle guard.
- `tests/`: model/serialization tests and a real Chrome ZIP save/import and extracted-package reopen tests.
